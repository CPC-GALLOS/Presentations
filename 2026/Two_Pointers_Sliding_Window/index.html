I
Primera cadena · ventana fija

¿Qué cambia de un bloque al siguiente?

Primera cadena: ventana de tamaño fijo.
El problema

¿Cuál es la suma máxima de un bloque de tamaño k?

La forma directa: sumar cada bloque desde cero.

int mejor = -1000000000;
for (int i = 0; i + k <= n; i++) {
    int suma = 0;
    for (int j = i; j < i + k; j++)
        suma += a[j];
    if (suma > mejor)
        mejor = suma;
}
cout << mejor << "\n";
La forma directa es sumar cada bloque desde cero. Las líneas resaltadas son el ciclo interno que vuelve a sumar todo el bloque.
Contar primero

¿Cuántas operaciones hace esto, aproximadamente?

ciclo de afuera

×
ciclo de adentro
k
→
recién ahí aparece
O(n·k)
Contar primero: el ciclo de afuera corre n veces, el de adentro k. Entonces n × k. Recién ahí aparece O(n·k). (Presiona → para revelar cada parte.)
¿Qué palabra hay que precisar?
desde cero

Cada bloque se suma completo otra vez, aunque casi todo se repite.

Pregunta: “¿Qué palabra de lo que acabamos de hacer hay que precisar?” Respuesta: desde cero. Luego: “¿Qué tiene en común un bloque con el siguiente?” → Casi todo. Quitas el primer elemento y agregas uno nuevo a la derecha.
Restar lo que sale, sumar lo que entra

Una suma y una resta por paso, sin importar cuánto mida el bloque.

→ PARA DESLIZAR LA VENTANA
“¿Entonces qué tendría que hacer para pasar de un bloque al siguiente?” → Restar lo que sale y sumar lo que entra. Presiona → para mover la ventana paso a paso (k = 3). Cian = entra, rosa = sale.
int suma = 0;
for (int j = 0; j < k; j++)
    suma += a[j];

int mejor = suma;
for (int i = k; i < n; i++) {
    suma += a[i];       // entra a[i]
    suma -= a[i - k];   // sale a[i - k]
    if (suma > mejor)
        mejor = suma;
}
cout << mejor << "\n";
¿Y ahora cuántas operaciones?

Primero el bloque inicial: k.

Después un solo ciclo de n, con dos operaciones por paso.

O(n)
“¿Y ahora cuántas operaciones?” Primero el bloque inicial, k. Después un solo ciclo de n, con dos operaciones por paso. Entonces O(n).
Idea clave

Ventana fija: el tamaño no cambia, la ventana solo se desliza.

Para que lo anoten.
¿Cuál es el error más común aquí?

Restar el elemento equivocado.

Pregunta de control: si k = 3 y estás en i = 5, ¿qué elemento sale?

Sale a[2], no a[3].

Deja que respondan antes de revelar. Respuesta: a[i − k] = a[2], no a[3].
II
Segunda cadena · ventana variable

¿Y si el tamaño de la ventana no es fijo?

Segunda cadena: tamaño variable.
El problema

¿Cuál es el subarreglo más largo cuya suma no pasa de S?

Tamaño variable: no puedes saber de antemano cuánto mide la respuesta.

más largo

Para probar cada longitud habría que revisar todos los subarreglos:

O(n²)
“¿Qué palabra de la pregunta anterior hay que precisar?” → Más largo. Para probar cada longitud, habría que revisar todos los subarreglos: O(n²).
¿Podemos avanzar sin volver a mirar lo que ya revisamos?

Agrandas por la derecha mientras cabe; cuando no cabe, achicas por la izquierda.

S = 6 · → PARA AVANZAR
Sí: una ventana con extremos izq y der. Presiona → paso a paso. El marco se pone rosa cuando la suma se pasa de S y hay que encoger.
int izq = 0;
long long suma = 0;
int mejor = 0;
for (int der = 0; der < n; der++) {
    suma += a[der];
    while (suma > S) {
        suma -= a[izq];
        izq++;
    }
    if (der - izq + 1 > mejor)
        mejor = der - izq + 1;
}
cout << mejor << "\n";
Pregunta para el grupo

¿Qué pasa si cambias while por if?

Sin responder todavía. Lo retomamos más adelante.

Pregunta para el grupo, sin responder todavía. Se contesta en el “error interesante”, más adelante.
Corrección preventiva

¿Siempre funciona la ventana variable?

No.

Con números negativos, sacar un elemento puede aumentar la suma, y el criterio de encoger deja de servir.

[ −4, 3, 2 ] → suma 1 sacas −4 → [ 3, 2 ] → suma 5

El criterio de esta clase asume elementos positivos.

Dilo justo después de introducir la ventana variable, antes de que la generalicen a cualquier arreglo.
Complejidad

¿Cuántas veces se mueve cada puntero en total?

Cada extremo solo avanza hacia la derecha, nunca retrocede. Cada uno se mueve a lo más n veces.

O(n)

Dos punteros que avanzan en la misma dirección y nunca retroceden.

Cada extremo solo avanza hacia la derecha, nunca retrocede. Entonces cada uno se mueve a lo más n veces: O(n) en total.
III
Tercera cadena · two pointers

Un par que suma X

Dos extremos que caminan el uno hacia el otro.

Tercera cadena: dos punteros desde los extremos.
El problema

En un arreglo ordenado, ¿hay dos números que sumen X?

Lo directo son todos los pares:

O(n²)
todos

Si el arreglo está ordenado, puedes descartar pares completos.

Si la suma actual es mayor que X, ¿qué conviene mover?

“¿Cuál es la palabra a precisar?” → Todos. Luego: si la suma actual es mayor que X, ¿qué conviene mover? → El extremo derecho, porque es el número más grande. Si la suma es menor, el izquierdo.
Mayor que X → mueve j · menor que X → mueve i

El extremo derecho es el más grande; el izquierdo, el más chico.

X = 11 · → PARA AVANZAR
Presiona → para mover los punteros. Cada paso descarta un par completo de opciones.
int i = 0, j = n - 1;
while (i < j) {
    long long s = a[i] + a[j];
    if (s == X) {
        cout << a[i] << " " << a[j] << "\n";
        return 0;
    }
    if (s < X)
        i++;
    else
        j--;
}
cout << "No hay\n";
¿Cuántas operaciones hace?

Cada paso mueve un puntero hacia el centro. Como mucho n pasos.

O(n)

+ el costo de sort que ya conocen.

Cada paso mueve un puntero hacia el centro. Como mucho n pasos: O(n), más el costo de sort que ya conocen.
Idea clave

Un arreglo ordenado permite descartar pares, no solo mirarlos.

¿Con qué se confunden?

La mayoría piensa que dos punteros siempre significa ventana.

¿El par que suma X es un bloque contiguo?

Deja que lo discutan. No: a[i] y a[j] son dos posiciones sueltas; lo de en medio no forma parte de la respuesta.
Error interesante · encoger con if en vez de while

Entrada: a = 1 1 1 4  S = 3

¿Cuántas veces tienes que encoger aquí?

der = 0, 1, 2 → suma 3, ventana válidader = 3 → suma 7, con if sale solo a[0]: suma 6, sigue inválida

La ventana sigue inválida y el programa sigue contando sobre ella. El while existe por esto.

No lo expliques antes de que lo intenten. Pregunta primero: “¿Cuántas veces tienes que encoger aquí?” Con if solo se saca un elemento por paso; hacían falta tres.
